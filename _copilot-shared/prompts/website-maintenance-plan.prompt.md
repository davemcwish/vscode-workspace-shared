# Website Maintenance Plan Prompt

You are helping create a beginner-friendly post-launch website maintenance plan.

Do not assume the website is finished just because it has launched. A website
needs an owner, a maintenance routine, and clear checks to keep it accurate,
secure, findable, and useful.

## Ask for missing context first

If the user has not already provided it, ask concise questions about:

- website type:
  - public website,
  - internal website,
  - static HTML/CSS site,
  - no-code site,
  - CMS site,
  - eCommerce site,
  - generated static report,
  - custom web application,
- platform or hosting provider,
- country or region the site is mainly for,
- where the business or organisation is legally based,
- who owns website updates,
- who owns domain and hosting renewals,
- who receives form submissions,
- whether payments, bookings, accounts, or newsletters are used,
- whether analytics are configured,
- whether the site uses plugins, themes, integrations, tracking pixels, or embedded third-party tools.

If the user does not know, explain the options in beginner-friendly language.

## Create the maintenance plan

Produce a plan with these sections:

1. Maintenance summary
2. Website ownership
3. Weekly checks
4. Monthly checks
5. Quarterly checks
6. Annual checks
7. Platform-specific checks
8. Security and resilience
9. SEO and content freshness
10. Accessibility and usability
11. Analytics and improvement
12. Social media and online presence
13. Escalation: when to ask for technical help

## Include maintenance checklists

Use clear checkbox lists.

Cover at least:

- content updates,
- broken links,
- contact forms,
- booking links,
- payment links if relevant,
- email delivery,
- domain renewal,
- hosting renewal,
- SSL/HTTPS,
- backups,
- CMS/plugin/theme updates if relevant,
- no-code platform billing and integrations if relevant,
- static-site deployment ownership if relevant,
- analytics review,
- SEO checks,
- local listing consistency,
- accessibility checks,
- mobile checks,
- image compression,
- privacy/cookie notices,
- user accounts and admin access,
- social profile links,
- reviews/testimonials,
- tracking pixels and third-party embeds.

## Output style

Use beginner-friendly language.

Avoid unnecessary technical detail unless the user asks for it.

End with a short "First month after launch" action list.
